# RTSH-OTT — Full Codebase Audit (2026-07-03)

Professional audit: security, bugs, structure, duplication, dependency health, and
industry-standard RN/Expo conformance. Findings verified against the working tree at
commit `8b0d55d` (+ uncommitted header/prefetch work). Each finding carries a severity,
a confidence rating, and a concrete fix. The prioritized plan is at the bottom —
execute phases in order; each item is a checkbox so `/anxheloo-task-plan-executor`
can drive it.

**Baseline (verified this audit):** `tsc --noEmit` clean · `expo lint` 1 warning
(`useOTA` deps) · i18n en/sq key parity perfect (276/276) · `.env`, `dist/`,
keystores gitignored · no stray `console.log`, no `any`, no untracked TODO debt.

---

## Verdict

The architecture is genuinely strong — the auth/token design (vault, single-flight
refresh, narrow logout trigger), the persistence boundaries, the realtime scheduler
discipline, the skeleton strategy, and the responsive module are all at or above
industry standard, and the docs explaining *why* are exceptional. What separates this
from a true gold-standard reference project is **not the app code — it's the missing
engineering scaffolding around it**: zero automated tests, no CI, no crash reporting,
no error boundary, and a handful of doc-vs-code drifts that undermine the "docs are
the contract" rule. Fix Phase 0 + Phase 1 below and this repo is legitimately
template-grade.

## A. Security findings

### A1. Stream access control is interim-only — sign-off needed before launch
**Severity: HIGH (accepted interim — make it a launch blocker, not a footnote)** · [CERTAIN]
- The custom `User-Agent` (`getStreamHeaders`) is a spoofable speed-bump by design.
- The pre-expiry re-sign (`POST /channels/playback/refresh`) is **disabled** — a signed
  URL expiring mid-watch 403s until an incidental refetch (`useChannelsQuery.ts`
  preserved block documents this).
- `expo-video` AES-128 key-request header forwarding is still unvalidated on a real
  stream (`TODO(anx 2026-06-02)` in `LivePlayer.tsx`/`VideoPlayer.tsx`), and the
  live-edge re-sync depends on unverified `EXT-X-PROGRAM-DATE-TIME`.
**Fix:** treat "signed/expiring URLs live + re-sign re-enabled + AES header validation
on a real RTSH stream" as one launch-gate work item, pending Henri's backend. Client
work is small (reinstate the preserved `refetchInterval` block).
> **Decision (Anxhelo, 2026-07-03):** scheduled as a **v2 check** — see Phase 3 below.

### A2. Forced logout leaves the previous session's data in the query cache
**Severity: MEDIUM (privacy/correctness)** · [CERTAIN — read both paths]
User-initiated logout clears the cache (`useLogoutMutation.onSettled → queryClient.clear()`),
but the **session-expired path** (`authRefresh.ts` 401/403 → `store.logout()`) does not.
After a forced logout, `['me']` (with `staleTime: Infinity`), playback decisions
(country/entitlement-evaluated), and profile-adjacent data survive in memory; a second
account logging in on the same launch inherits them (`['me']` never refetches by design).
**Fix:** clear the cache at the single chokepoint — either call `queryClient.clear()`
inside the 401/403 branch of `refreshAccessToken`, or (cleaner) have `store.logout()`
emit and clear via one shared helper both paths use.

### A3. Preview builds ship arbitrary-cleartext exceptions
**Severity: MEDIUM** · [CERTAIN — `app.config.ts`]
`ALLOW_CLEARTEXT = IS_DEV || IS_PREVIEW` sets `NSAllowsArbitraryLoads: true` and
`usesCleartextTraffic: true` in **preview** builds too. Preview is internal-distribution,
but preview should mirror production (that's its job) — and the backend is now HTTPS.
**Fix:** scope cleartext to `IS_DEV` only; if the dev backend must be reachable from
preview, use an iOS `NSExceptionDomains` entry + Android `networkSecurityConfig` for
that one host instead of a blanket exception.
> **Decision (Anxhelo, 2026-07-03): keep as is.** Dev + preview retain the cleartext
> exception (both are internal builds that may point at the plain-HTTP dev backend);
> production ships with none — which the config already guarantees. Closed, won't-do.

### A4. 14 npm audit vulnerabilities (1 high) + 15 packages behind SDK 56 patches
**Severity: MEDIUM (all in the expo config-plugin/build chain, not runtime)** · [CERTAIN — `npm audit`, `expo-doctor`]
The whole chain resolves through outdated `@expo/config-plugins`; `expo-doctor` fails on
15 patch-level mismatches (expo 56.0.6 vs ~56.0.13, expo-router 56.2.7 vs ~56.2.12, etc.).
**Fix:** `npx expo install --check` (patch-level, safe), then re-run `npm audit` +
`expo-doctor`. Also bump `@tanstack/react-query`, `axios`, `i18next` minors (`npm outdated`).

### A5. STOMP connects with an empty Bearer on cold boot
**Severity: LOW** · [HIGH — code-read; behavior inferred from the boot flow]
`realtime/client.ts` `beforeConnect` reads `token ?? ''`. On cold boot
`isAuthenticated` is true but `token` is null until the first 401-refresh, so the
CONNECT frame carries `Bearer ` → rejected → 2s reconnect churn until the token lands.
**Fix:** in `useRealtimeConnection`, gate `connectRealtime()` on `token != null`
(subscribe to the store), or skip activation in `beforeConnect` while token is empty.

### A6. What's already right (keep it that way)
[CERTAIN] Refresh token in keychain via a single vault owner · access token memory-only ·
`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` accessibility · 401 single-flight through a bare
client · auth routes excluded from refresh · parental PIN stored as SHA-256 (better than
docs claim — see E3) · mock server dev-env-gated · `.env` untracked · Zod at the auth
boundary · no PII in logs.

## B. Bugs / correctness

### B1. Analytics module is built, documented as live, but disabled by comments
**Severity: MEDIUM (drift + dead weight)** · [CERTAIN]
`useAnalytics()` / `useWatchTracking` / `onError → track(STREAM_ERROR)` are commented out
in `(app)/_layout.tsx` and `channel/[id].tsx`, while CLAUDE.md/ARCHITECTURE.md describe
them as mounted. Spec MW.14/Mon.6 mandates telemetry for v1.
**Fix (decide one):** (1) re-enable behind `settings.analyticsEnabled` once the backend
ingestion exists; or (2) keep disabled but sync the docs and add a plan item. Don't leave
code and contract disagreeing.

### B2. `useOTA` effect has missing deps (`t`, `updateModalSlice`)
**Severity: LOW (lint warning, stale-closure risk on locale switch)** · [CERTAIN — lint output]
**Fix:** include the deps (both are stable) — clears the only lint warning.

### B3. Image prefetch ignores data-saver / cellular settings
**Severity: LOW (UX/bandwidth)** · [HIGH]
The new `useImagePrefetch` on Home + Guide warms **every** logo and cache-busted snapshot
on each refetch — on cellular, with `dataSaverEnabled: true`, this still burns data the
user asked to save.
**Fix:** early-return in `useImagePrefetch` (or at call sites) when
`dataSaverEnabled && connectionType === 'cellular'` — both already live in the store.

### B4. Known-and-accepted gaps (tracked, no action this pass)
Expired-refresh boot flash (5.X.5) · static refresh token (backend decision) ·
MMKV plaintext (5.X.10, whitelist pending 5.X.17) · `user` blob unbounded (5.X.17).

## D. Industry-standard gaps (the real distance to "gold standard")

### D1. Zero automated tests
**Severity: HIGH — the single biggest gap** · [CERTAIN — no jest config, no test files]
The codebase was *designed* for testability (pure `realtime/midroll.ts`, `utils/epg.ts`,
`utils/datetime.ts`, `lib/tokenVault.ts`, `utils/resolveStreamSource.ts`, `utils/pin.ts`,
mock adapter) and then never tested. Any regression in mid-roll scheduling, EPG boundary
math, or token persistence ships silently.
**Fix:** `jest-expo` + `@testing-library/react-native`. Start with the pure core
(highest value/effort ratio): midroll scheduling, `findPlayingProgram`/`programProgress`,
`toDateKey`/day math, tokenVault remember-me matrix, `resolveStreamSource`/
`inferContentType`, auth Zod schemas. Then RNTL for `AdOverlay` (completion paths),
`ParentalPinModal`, and the 401-refresh interceptor against the mock adapter.

### D2. No CI
**Severity: HIGH** · [CERTAIN — no `.github/`]
Verification is manual convention ("run lint + tsc before claiming done").
**Fix:** GitHub Actions on PR + main: `npm ci` → `tsc --noEmit` → `expo lint` → `jest`.
Add `npx expo-doctor` as a scheduled (weekly) job so dependency drift surfaces itself.

### D3. No crash reporting / no root error boundary
**Severity: MEDIUM** · [CERTAIN — Sentry absent from package.json; no ErrorBoundary export]
Both are already tracked (5.X.12, "no error boundary at root") — still open. A render
crash in any tab kills the app invisibly.
**Fix:** install `@sentry/react-native` (config plugin, EAS-managed DSN), export
`ErrorBoundary` from `src/app/_layout.tsx` (expo-router idiom) with a branded retry
screen. This also un-blinds the swallowed boot-wiring catch and font-load failures.

### D4. `react-native-country-picker-modal` is unmaintained
**Severity: MEDIUM (library health)** · [HIGH — last publish ~4y; already forced the
`platforms` web exclusion via its broken `react-async-hook` dep]
**Fix:** replace with a small owned picker (a `SelectInput` + static country list via
`i18n`/`expo-localization`) or a maintained alternative. Removes a legacy dep and the
web-platform workaround.

### D5. Accessibility coverage is partial
**Severity: MEDIUM (store review + public-broadcaster obligation)** · [HIGH — grep sample]
Primitives (`ReusableBtn`, `IconButton`, `Switch`, `Checkbox`, toggles, `PlayerControls`)
carry a11y props; content rows do not: `StationRow`, `ProgramRow`, `GuideRow`,
`HeroCarousel`, `RadioMiniPlayer`, `ParentalPinPad`, `SheetOptionRow`, `ModalWrapper`
buttons.
**Fix:** one a11y pass: `accessibilityRole` + `accessibilityLabel` (+ `accessibilityState`
for selected/disabled) on every interactive leaf; VoiceOver/TalkBack smoke test on Home,
Guide, player, PIN pad. RTSH is a public broadcaster — this will be asked for.

### D6. Dependency currency policy
**Severity: LOW (process)** · [CERTAIN]
SDK 57 is out; project is on 56 (fine — TV pass 22.18 should not ride an upgrade).
**Fix:** adopt the policy: stay current on **patches** within the pinned SDK
(`npx expo install --check`, monthly), plan **SDK upgrades** as explicit plan-phase items
(SDK 57 after the mobile phase is approved). Record it in STANDARDS.md.
