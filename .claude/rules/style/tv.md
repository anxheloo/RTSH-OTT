# TV / D-pad focus — RTSH-OTT conventions

Scoped part of `rules/STYLE_GUIDE.md`; loads when you read or edit a file named above.

## TV / D-pad focus (`@/tv`)

Android TV / STB run the **same codebase** (react-native-tvos alias, `EXPO_TV=1` prebuild). All TV affordances live in the portable `src/tv/` module and are **inert off-TV** — so phone/tablet stays byte-identical. Never fork a component for TV; gate on `isTV` and no-op.

- **`isTV`** (`Platform.isTV`) — the runtime leanback-build flag. Distinct from `@/responsive`'s window `deviceClass` (`tv`) and `utils/device.ts`'s `getDeviceClass()` (`TV|STB`, backend). Use `isTV` for D-pad/focus behaviour.
- **Focus ring** — an interactive primitive tracks focus with **`useTVFocus()`** (`{ focused, focusProps }`, `focusProps` = `onFocus`/`onBlur`) and applies **`tvFocusHighlight(colors.focus, focused)`** **LAST** in its `style` array (it returns `undefined` off-TV *and* when unfocused, so it never clobbers the base style). This is already wired into the shared primitives (`ReusableBtn`, `ListRow`, `ChannelCard`, `ProgramRow`, …) — reuse them; don't hand-roll a ring.
  - **Full-width elements must pass `{ scale: false }`** — `tvFocusHighlight(color, focused, { scale: false })`. The default 1.05 scale "pops" compact controls (cards, icon buttons, PIN keys) but on a full-width element (search bar, list rows) it pushes the box ~5% past the screen edge → **horizontal overflow**. Border-only there. Already applied to `SearchBar`, `ListRow`, `SheetOptionRow`, `GuideRow`, `SearchResultRow`, `StationRow`.
  - **List rows want fill, not a ring** — a thin ring on a full-width transparent row is invisible on a 10-foot screen. `ProgramRow` (and the TV route-menu rows) instead render a **solid fill (`colors.surfaceHigh`) + a bold left accent bar (`colors.focus`)** when `focused` (only ever true on TV, so no `isTV` gate needed). Prefer this for any full-width drawer/list row.
  - **The ring must contrast with the FILL it sits on, not with the page background.** `tvFocusHighlight` draws a *border on the focused control itself*, so a ring the same colour as that control's `backgroundColor` gives no focus feedback at all — and on a pointerless device, a control you can't see focus on is a control you can't operate. **Fixed at the token 2026-08-10:** `colors.focus` is now `#FFFFFF` (dark) / `#0B0B0F` (light), so plain `tvFocusHighlight(colors.focus, …)` is correct on filled *and* transparent controls, including `ReusableBtn`'s `primary` and `destructive` variants. **Until then `focus` was `#EB122F` — the same value as `primary`** — which drew a red ring on every red-filled CTA app-wide (auth submit, confirm buttons, the parental PIN confirm); `RadioPlayer` carried a one-off `colors.onPrimary` override for it, now removed. **The rule that outlives the fix:** if you introduce a fill whose colour approaches `colors.focus`, pass a contrasting token explicitly rather than assuming the default ring shows — that is why `AdOverlay` rings in white and `PlayerControls` rings in `PLAYER_COLORS.brand` over video. See `architecture/android-tv-stb.md → Known gaps` for the decision record.
- **Focus zones** — wrap a region in **`TVFocusZone`** (a `TVFocusGuideView`, a bare fragment off-TV): `autoFocus` redirects the D-pad to the first focusable on entry; `trapFocus{Up,Down,Left,Right}` traps focus inside a drawer/overlay. Set `autoFocus={false}` when a specific child claims initial focus via `hasTVPreferredFocus` (so the guide doesn't fight it).
  - **Initial focus** — pass `hasTVPreferredFocus` to the control that should own focus when a screen/drawer mounts (react-native-tvos prop; `ProgramRow` forwards it). The channel guide drawer defaults focus to the **now-airing** row this way.
- **Cross-scroller focus is unreliable; use ONE list.** RN can't reliably hand the D-pad **between two scrollers** (a horizontal date strip above a vertical `ScrollView`). The fix is the same as [Lists](screens-and-lists.md#lists--screen-composition): a **single vertical `FlatList`** with the other region as `ListHeaderComponent`, so focus flows within one list (it also auto-scrolls the focused row into view). See `channel/[id].tsx` → `tvGuideList`. A plain `ScrollView` list additionally needs `TVFocusZone` + an `onFocus`-scroll. (Historical note: a `withAndroidTVFocusFix` config plugin used to force `enableCustomFocusSearchOnClippedElementsAndroid=false` for the RN 0.80+ #1087 regression — **deleted 2026-07-28**, since react-native-tvos 0.86 already ships that flag defaulting to `false`. The single-`FlatList` rule above is what actually carries the D-pad, and always was.)
- **Nested focusables trap the D-pad.** A focusable wrapper around focusable children (a pressable strip containing pressable buttons — `RadioMiniPlayer`; a full-screen tap overlay over control buttons — `PlayerControls`; **a backdrop + sheet wrapping the modal's buttons — `ModalWrapper`**) makes the inner controls unreachable. Drop the wrapper from the focus order on TV.
  - **Write it `focusable={isTV ? false : undefined}`, NOT `focusable={!isTV}`.** The `!isTV` form passes an explicit `true` on touch builds, and `TouchableOpacity` defaults `focusable` to **false when it has no `onPress`** — so on a tap-catching wrapper (exactly the kind this rule targets) `!isTV` *adds* Android focusability that wasn't there before. `undefined` leaves the default untouched, which is what "inert off-TV" has to mean. Caught 2026-08-17 while fixing `ModalWrapper`; the two earlier call sites both have an `onPress`, so they were unaffected and the older form survived unnoticed.
  - **Unfocusing the wrappers is necessary but NOT sufficient inside an RN `<Modal>`.** A `<Modal>` is its own window; with the wrappers out of the focus order nothing inside is focused at all and the D-pad has no entry point. Give the primary action **`hasTVPreferredFocus={isTV ? true : undefined}`**. `ReusableBtn` already forwards it via `...rest` — no prop plumbing needed. **Every global confirmation was unusable on TV until this landed** (device-verified 2026-08-17: logout, delete account, retry and the blocking force-update CTA were all visible but unpressable).
  - **When the inner control only exists to split a mobile gesture, drop the split instead.** `ProgramRow` splits its press targets on mobile (body = expand the description, play glyph = play) — but a remote has no second tap target to disambiguate, so on TV the glyph is rendered as a plain `View` (never a nested pressable), row press keeps playing, and the *secondary* action rides **focus** instead (the parent sets `expandedProgramId` from `onFocus`). Prefer re-mapping a mobile-only split onto D-pad focus over making both targets focusable: focus is unique, so a "only one open at a time" invariant falls out for free from the same state field.
- **Overlays must clear a clipped/absolute parent via `Modal`.** The header route menu escaping `BrandHeader`'s `overflow: hidden` renders in a **`Modal`** (`transparent`, `onRequestClose` closes on remote Back) so it paints above the whole screen incl. the tab bar — not an absolute `View` (which is clipped to the header). A drawer inside a full-screen container (`channel/[id]`'s guide) can stay an absolute `View`.
- **TV navigation = header, not bottom tabs.** The bottom tab bar is **hidden on TV** (`tabBarStyle: { display: 'none' }` when `isTV`; `useTabBarHeight()` returns 0) — a bottom bar is poor 10-foot UX. Sections switch from **`TVNavButton`** (a route-menu `Modal` drawer in `BrandHeader`, TV-only, right side). Player controls auto-hide on TV through **`useTVAutoHide`** (any remote key brings them back) — see the next rule.
- **Hiding focusable chrome on TV: unmount it, and leave exactly one focus holder.** Fading (`opacity: 0`) is not hiding on TV — the faded button keeps focus and OK still presses it. Unmount the buttons instead, and make one full-screen layer focusable (`hasTVPreferredFocus`) while they are gone: remote keys reach JS only through the focused view, so with nothing focused no key can bring the chrome back. Reveal on the key **release** (`eventKeyAction === 1`), never the press, or the control that mounts and takes focus catches the same OK. On the player, OK on that layer also pauses/resumes, as YouTube and Netflix do. `PlayerControls`' tap layer + `channel/[id]` are the reference.
- **No endless animations on TV.** react-native-tvos makes a synchronous binder call to `system_server` on every View props update, so a looping Reanimated animation (`withRepeat(..., -1)`) costs one system call per animated view per frame — enough to ANR a low-end TV box (REACT-NATIVE-RTSH-OTT-1K). Gate the loop on `isTV` and render a static pose, as `Skeleton` and `Equalizer` do. Finite animations are fine. See `architecture/android-tv-stb.md → Known gaps`.
- **Never** call `scaled()`/`isTV` branches inside deep feature components for layout — layout scale rides `@/responsive` tokens; `@/tv` is only for focus/D-pad interaction.

## Things worth avoiding

| Pattern | Preferred approach |
|---------|-------------------|
| A native-interop control (`@expo/ui` `Host`/`Picker`, any Compose/SwiftUI island) on a screen that must work on TV | Give it an `isTV` branch built from plain RN (`SelectInput` renders `SegmentedChoice` on TV). Compose owns its own focus system and does **not** hand the D-pad back to React Native, so focus enters the island and never leaves — everything below it on the screen becomes unreachable. Device-verified 2026-08-17: this made the register form's terms checkbox + submit button unreachable, i.e. **signup was impossible on Android TV**. It is invisible on touch, and `@expo/ui` does not claim TV support. |
| `overflow: 'hidden'` on a focusable element (the `TouchableOpacity`/`Pressable` that takes D-pad focus) | Keep `borderRadius` and the focus ring on the focusable; put `overflow: 'hidden'` on an inner `View` (`flex: 1`, same radius) that holds the content. On Android TV, once focus leaves a focusable view that clips its own children, it stops drawing them. It is native-only (no JS prop change is needed to trigger it) and invisible on touch. Device-verified 2026-10-20 on `ChannelCard`: the Home grid blanked every card the remote had passed over. |
